# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

3DTD is a Unity tower defense game whose twist is the third dimension: players stack building blocks and attach towers to any face, and enemies fly along waypoint paths through 3D space. It is in active development again.

- This folder is the git repo root (README, `.gitignore`, this file, `.claude/rules/`, `tasks/`, `Tools/`, `docs/`).
- `3DTD/` is the Unity project root. **All paths below are relative to it.**

## Tooling

- The editor is pinned to **Unity 6000.5.8f1** (Unity 6.5, `ProjectSettings/ProjectVersion.txt`), with URP 17.5 and VFX Graph 17.5. Scripts compile as C# 9, so avoid newer language features.
- The project was upgraded from Unity 2021.3.7f1 / URP 12 on 2026-10-01; the pre-upgrade working tree is kept on the local branch `backup/pre-unity6-upgrade`. Opening it in a different editor version runs another one-way upgrade. Ask before doing that.
- URP 17.5 only has the render graph path: `ScriptableRenderPass.Execute`/`Configure`/`OnCameraSetup` and `renderer.cameraColorTargetHandle` no longer exist, so renderer features must implement `RecordRenderGraph`.
- TextMesh Pro now ships inside `com.unity.ugui` 2.5. The shaders in `Assets/TextMesh Pro/Shaders` must match that version (they were refreshed from the package's "TMP Essential Resources"); old TMP shaders render text invisible.
- The project has no build scripts, no linter, and no asmdefs. All game code compiles into `Assembly-CSharp` in the global namespace. EditMode tests live in `Assets/Editor/Tests/` and compile into `Assembly-CSharp-Editor` (an asmdef could not reference `Assembly-CSharp`). Run them with `-runTests -testPlatform EditMode -testResults <file.xml>` instead of `-quit` in the command below.
- `dotnet build` won't work: the `.sln`/`.slnx` and `*.csproj` files are generated by the Editor and gitignored. To compile-check from the CLI, run this from the workspace root (it needs the matching editor installed and the project closed in the Editor):
  ```
  "/Applications/Unity/Hub/Editor/6000.5.8f1/Unity.app/Contents/MacOS/Unity" -batchmode -quit -nographics -projectPath "$(pwd)/3DTD" -logFile -
  ```
  Compile errors appear in the log as `error CS####`.
- `Tools/BalanceDashboard/` (repo root, outside the Unity project) is a balance analytics dashboard. Run `python3 Tools/BalanceDashboard/extract.py` after changing towers, upgrades, enemies, waves, difficulty profiles or scenes, then open its `index.html`. The extractor parses Unity YAML without Unity. `engine.js` mirrors the C# combat and economy logic (FireCycle, damage/armor/shield/regen rules, income, prices, spawning), so update it when you change an `ActionStrategy`, `Enemy` damage handling, `Spawner`, `GameManager` economy or `UpgradeManager` rules. Its README describes the balancing workflow:
  - `write_waves.py` generates every level's waves from `wave-design.json` (via `wavegen.js`), writes the WaveData assets and assigns them to the Spawners.
  - `acceptance.py` runs the headless balance checks (meta-agent sweeps per level and difficulty).
- Input uses the legacy `Input` manager, not the Input System package. Esc first cancels a placement, then closes the tower panel, then pauses; 1-9 and 0 pick build tiles; Delete or Backspace (the Mac Delete key) sells the selected building, except while paused or after game over; O toggles the HUD.
- UI tooling (`UIRedesignBuilder.BuildAll`, `UICapture.Run`, `UIPlaytest.Run`, menu 3DTD > Progress): see `.claude/rules/ui.md`. Re-running the builder overwrites manual edits to the UI prefabs; edit the builder instead.
- Level tooling (`BeginnerLevelBuilder.Run`, `LevelPlaytest.Run`): see `.claude/rules/levels.md`. Beginner 02-05 maps are defined in the builder; edit it, not the scenes or map prefabs.
- Performance tooling (`PerfBenchmark.Run -perfSuite <suite>`, `PerfBenchmark.BuildPlayer`, `ProfileReport.Run`; needs graphics): see `.claude/rules/perf.md`. Results and history are in `docs/HANDOFF.md` (repo root).
- Effect tooling (`ProjectileVisualsBuilder.Run`): see `.claude/rules/effects.md`. Re-running it overwrites the generated prefabs; edit the recipes in `ProjectileVisualsBuilder.Recipes.cs` instead.
- Burst 1.8.30 is pinned in `manifest.json`; Collections and Mathematics come built in. Each job type's reflection data and the Burst runtime are warmed up at startup (the `WarmUpJobs` methods), not on the first shot.

### Editing Unity files from outside the Editor
- Scenes, prefabs, and assets reference scripts and assets by the GUID in their `.meta` file. When you move or rename a file, move its `.meta` with it, and keep a script's class name identical to its file name.
- Renaming a serialized field drops its value in every prefab and scene unless you add `[FormerlySerializedAs("oldName")]`.
- To check whether a script is used anywhere, take the `guid:` from its `.cs.meta` and grep for it in `Assets/**/*.unity`, `*.prefab` and `*.asset`.

## Scenes

Build order (`ProjectSettings/EditorBuildSettings.asset`): `MainMenuLevel` (index 0, which `PauseMenu.LoadMainMenu` loads), `Beginner Level 01` to `05`, then `Intermediate Level 01/02`. The scenes `MainMenu` and `CameraTest` exist but are not in the build; the old Beginner Level 02/03 were retired to `Scenes/Disabled/` (with their map prefab in `Prefabs/Maps/Disabled/` and wave set in `WaveData/Disabled/`).

Beginner Level 01 is hand-built; 02-05 are generated by `BeginnerLevelBuilder` (single lane each, one 3D idea and one favoured strategy per map; the per-map designs are in `.claude/rules/levels.md`).

Each level scene contains:
- `Prefabs/GAME_SETUP.prefab`, which holds `GameManager`, `SelectionManager`, the camera controllers and the nested `Prefabs/UI/HUD Canvas.prefab` (HUD, build rail, tower panel, pause overlay; see UI below).
- The map geometry, which comes from `Prefabs/Maps/*` and is made of `BuildingBlock`s with `AnchorPoint`s.
- A `Spawner` tagged `Spawner`, an `End` trigger tagged `End`, and `Waypoints` whose children are tagged `Waypoint`. `GameManager.Start` finds the Spawner and End by tag, so those tags are required.

`MainMenuLevel` reuses the game scene setup with `GameManager.isMainMenu = true`, which auto-starts a wave as an animated backdrop, and holds `Prefabs/UI/Main Menu Canvas.prefab`.

## Architecture

The game code lives in `Assets/Scripts/`. A few project scripts sit loose in `Assets/`: `ShootingPointReference`, `EnemyPopSoundSpawn`, and `DebugScript`.

### Global state
- These classes expose a `static Instance` singleton: `GameManager`, `Spawner`, `End`, `BuildingManager`, `PauseMenu`, `UpgradePanelManager`, `TooltipService`, `PlacementPreview` and `EnemyPopSoundSpawn`. `SelectionManager` keeps its state in static fields. `GameSettings` (static) carries the difficulty chosen in the level select's difficulty popup.
- `Spawner`, `End`, and `EnemyPopSoundSpawn` assign `Instance` in `Start`, not `Awake`, so it is still null during other objects' `Awake` (and other `Start`s may run first: the HUD finds the Spawner by tag).
- Persistent player data (`Scripts/Progress/`): `PlayerProgress` (medals per level and difficulty, Research, owned meta upgrades; PlayerPrefs `3DTD.Progress`), `GameOptions` (Options screen settings; PlayerPrefs `3DTD.Options`; applied on every scene load; in the Editor it restores the URP asset and quality level on exiting play mode), `SaveGame` (one autosave slot `persistentDataPath/savegame.json`, written at every wave end, restored by Continue) and `MetaUpgrades` (totals of owned meta upgrades).
- `GameManager` owns money, lives, round, and game speed, and raises change events (`OnMoneyChanged`, …) that the UI subscribes to.
  - Game speed drives `Time.timeScale`, so pausing sets it to 0.
  - Difficulty comes from a `DifficultyProfile` asset (`ScriptableObjects/Difficulty/`, assigned on GAME_SETUP's GameManager): start money (+ the scene's `extraStartingMoney`), lives, price multiplier, income multiplier per round, end-of-wave bonus, refund rate, enemy speed/HP, armor/shield bonus and the win round. Without profiles (main menu) the legacy fields are used.
  - Money from popped layers goes through `GameManager.AddIncome` (fractional income is banked; `OnMoneyChanged` is raised at most once per frame, in `LateUpdate`); prices through `GameManager.Price` / `PriceOf`.
  - An enemy that reaches `End` costs `enemy.Id + 1` lives. `RestoreLives` gives lives back, never above `StartingLives`.
  - `Spawner` declares the game won when the win round is cleared (at wave end, with lives left); `GameManager.GameWon` records the medal in `PlayerProgress`. `GameOver` deletes the autosave.
  - Meta upgrades (outside the main menu) add start money, lives (not on Impossible), income, wave bonus, a price discount and refund points, and `Tower.Start` adds their stat bonuses as modifiers. The balance tools model them only in veteran mode (every meta upgrade owned: `engine.js` setting `meta: full`, `acceptance.py --meta full`, the dashboard's Meta selector); the default is a fresh profile. Mirror changes to `MetaUpgrades` or the GameManager economy hooks in `engine.js`.

### Building and placement (the 3D part)
- **Build palette.** `GameManager.buildingPrefabs`, set per scene on GAME_SETUP, defines what the player can build. `BuildingManager` (the build rail) creates one `BuildTile` per prefab (hotkeys 1-9, 0). Nothing is selected by default; selecting a tile starts placement and `GetSelectedBuilding()` returns its prefab (null otherwise).
- **Buildable objects.** Everything buildable derives from `Building` (name, description, sprite, `Cost`). That includes towers and building blocks.
- **Placement.** An `AnchorPoint` is a clickable marker on one face of a block. On `OnMouseDown` (ignored while the pointer is over UI, checked with `UIPointer.IsOverUI`, which counts only canvas hits: `EventSystem.IsPointerOverGameObject` is also true over anything the Main Camera's `PhysicsRaycaster` hits, i.e. the whole map) it checks money, casts a 1-unit ray along its forward axis against its `layerMask` to see whether the face is occupied, and then instantiates the selected prefab at the anchor's position and rotation. A building's **forward** axis is therefore the face normal, and a tower can face any of six directions. `Tower.RotateTower` maps those directions to Euler angles and is known to be buggy. The price paid is recorded with `Building.AddInvestment`, the palette index with `Building.MarkPlacedByPlayer` (the autosave rebuilds those buildings). Hovered anchors feed `PlacementPreview` (ghost hexagon, range circle, tower icon).
- **Selection.** `Selectable.SelectThis()` sets `SelectionManager.CurrentlySelected`, which fires the static `OnSelectionChange` event, and `UpgradePanelManager` rebuilds its panel in response.
- **Selling.** `Selectable.SellThisTower` refunds `Selectable.GetSellValue`: everything invested (purchase and upgrades at the prices paid) × the profile's refund rate × the WORTH stat, and clears the selection. A building block can only be sold when no tower is attached to any of its six sides (`Selectable.CanSell`, raycasts).

### Tower system (`Scripts/Tower/`, `Scripts/Entities/Tower.cs`)
Towers are built by composing components on one prefab (`Prefabs/Tower/*`):
- **`Tower`** wires the parts together. Every `Update` it rescales the `Targetter` when RANGE changed and calls `actionStrategy.ExecuteAction()`.
- **`StatsManager` plus a `StatsScriptableObject`** (a "StatsConfig" asset) holds the base value for each `Stat.StatType`.
  - The configs are stored next to the code in `Scripts/Tower/Towers/<TowerName>/`.
  - Read stats with `StatsManager.GetStatValue(StatType)`, which returns -1 for a missing stat. Use `GetFireInterval()` (FIRERATE clamped to `StatsManager.MinFireInterval`) and `GetReloadTime()` for timers.
  - `Stat.GetValue()` adds the base value and the sum of all bonuses, then applies each modifier as a compounding percentage; the result is cached until an upgrade changes the stat.
  - FIRERATE is seconds between shots: "+X% fire rate" is a modifier of −X/(100+X)·100 (+25% → −20, +100% → −50). Module descriptions use that convention.
- **`Targetter`** is a child trigger collider that tracks the enemies inside it and picks one by `TargetBehaviour`:
  - FIRST and LAST use `Enemy.DistanceTraveled`.
  - STRONGEST uses the enemy `Id`.
  - NEAREST and FARTHEST use distance.
- **`ActionStrategy` subclasses** (`Tower/ActionStrategies/`) implement all firing behaviour: fire rate, magazine and reload, and either spawning projectiles or dealing direct damage.
  - Timing goes through `FireCycle` (`Tower/FireCycle.cs`): leftover time carries over and several volleys can fire in one frame, so damage doesn't depend on FPS or game speed. `VolleyAge(i)` is how overdue volley i of the frame was; its projectiles start that far along. Keep new strategies on it.
  - Projectiles of the Round, Basic, Bomb and Cluster kinds (Laser, Core, Bullet Dispenser, rockets and bomblets, starfighter cannons and ordnance) are data in `ProjectileSystem` (`Scripts/Combat/`): strategies call `ProjectileSystem.Fire(prefab, Shot)` with the current stats and the volley age. Each frame a Burst job grids the enemies (`EnemyRegistry`), a parallel job moves every projectile and sweeps its capsule against the enemies' own movement (rockets home in 1/120 s sub-steps) and advances those without a hit, and the main thread applies hits and expiries in projectile order. Projectiles only hit enemies (they pass through blocks, towers and anchors). Blasts query `ProjectileSystem.Instance.OverlapEnemies`.
  - `ProjectileArchetype` reads each projectile prefab once (its `Projectile*` component, its collider as the hit shape, the `PolygonProjectileScript` effect fields), so the prefabs stay the authoring source. Pulse and Hindrance stay pooled GameObjects (`ProjectilePoolManager.GetOrCreate`, returned through `OnProjectileDeath`).
  - Laser and Core lead their shots (`aimWithLead`, `AimUtility.PredictIntercept`); the Bullet Dispenser never aims, its barrels fire along fixed directions. Spread and other gameplay randomness use the tower's own seeded `Tower.Rng`.
  - Damage goes through `Enemy.TakeDamage(damage, DamageType, tower)`, which also credits the tower's `DamageCount`; the tower that finishes an enemy off gets `Tower.Kills`. Damage types matter: PROJECTILE (Laser, Core, Bullet Dispenser, Sniper, starfighter cannons), EXPLOSIVE (rockets, bomblets, pulse, starfighter ordnance), MAGIC (Beam, flamethrower). Mine Factory mines are EXPLOSIVE.
  - Bomblets of cluster rockets get `clusterDamageShare` / `clusterRadiusShare` of the rocket's damage and radius. `BeamSlowUpgrade` makes beam ticks slow enemies.
  - Effect sizes follow stats: muzzle, flight and impact effects scale with the shot's SIZE, explosions with the blast radius (`ProjectileSystem.BlastImpactScale`, 1 at RADIUS 0.8, growing a bit slower than the radius, capped).
- **Hangar Tower** (`HangarTowerActionStrategy` + `Starfighter`) and **Mine Factory** (`MineFactoryActionStrategy` + `Mine`) work differently from the other towers: see `.claude/rules/towers.md`.
- **`UpgradeManager`** holds an array of `UpgradePath`s, each with up to three `UpgradeModule` tiers.
  - A module has a price, one or more `StatUpgrade`s (each a flat bonus or a percentage modifier on a single stat), `Upgrade` MonoBehaviours for changes in behaviour (`Tower/Upgrades/`), and visuals to switch on or off.
  - For example, `ChangeActionStrategyUpgrade` swaps the tower's strategy.
  - `CheckPathBlocking` enforces the cross-path limits: at most two paths can reach tier 1 or tier 2, and only one path can reach tier 3.
  - `RemoveUpgrade` is mostly unimplemented (`NotImplementedException`).

To add a tower type, write an `ActionStrategy`, create a StatsConfig, build a prefab in `Prefabs/Tower/`, and add the prefab to `buildingPrefabs` on the scene's GAME_SETUP.

### Effects (`Scripts/Effects/`)
Effects are never instantiated per shot or hit. Play one-shots with `EffectPlayer.Play(prefab, position, rotation, scale, maxLifetime, age)`, and attach flight effects with `EffectPlayer.Attach(...)`, which returns a `FlightHandle` (`SetPose`, `Release`). `EffectPool` picks the backend per prefab:
- **Budgets the user allowed:** effects cast no shadows; a batched system shows at most 32 particle lights (`BatchedEffect.MaxLightsPerSystem`) and pooled copies share 64 (`EffectPlayer.LightBudget`); one sound clip plays at most 4 voices at once (`EffectAudio`). Everything else plays at every speed: don't add caps, skips or culls for performance.
- Backends (`BatchedEffect`, `FlightBatch`, pooled `EffectInstance`), `DeathEffectRenderer`, `TracerRenderer`, `TowerBeam` and the generated projectile looks / `VisualUpgrade`s: see `.claude/rules/effects.md`.

### Enemies and waves
- **One enemy prefab.** Every enemy is an instance of `Prefabs/Enemies/Default Enemy.prefab`, which uses Bloons-style layered health.
  - An enemy's type is a `Shape` combined with an `EnemyColor`, and `Id = (int)shape * 10 + (int)color`.
  - `Enemy.HandleDamageTaken` resolves a hit layer by layer: when a layer's health reaches 0 the player gains 1 money, the enemy drops one color (`SetLayer`) and leftover damage carries over. After RED it moves to the previous shape at BLACK. Id 0 (red tetrahedron) dies for good.
  - Enemies with `Shape.BOSS` (600 HP) die at once instead.
  - **Traits** (`EnemyTrait` flags, set per WaveData entry): Armored (PROJECTILE hits lose the armor value, EXPLOSIVE three quarters of it, MAGIC ignores it, min 40% of the hit), Shielded (the first hits are absorbed), Regenerating (regrows layers after 3 s without damage). Values are in `Enemy.cs` (`ArmorValue`, `BaseShieldHits`, `Regen*`) plus the profile bonuses.
  - **Pooling.** The `Spawner` pools enemies: a dead or leaked enemy is deactivated (`ReleaseEnemy`) and reused after 3 s via `Enemy.Initialize`. It also prewarms the pool a few enemies per frame towards the next wave's size (`IsPrewarming`, `EnemiesCreated`). Check `Enemy.IsAlive` instead of null when holding enemy references; `Enemy.SpawnSerial` tells pooled lives apart (`Targetter` and `EnemyRegistry` use it).
- **Id-indexed arrays.** The prefab's `allPossibleShapes` (child meshes) and `allPossibleEnemyData` (`ScriptableObjects/EnemyData/`) are both indexed by Id. If you add a shape or color, keep the enums and both arrays aligned.
- **Movement.** Enemies move in straight lines between waypoints and accumulate `DistanceTraveled`; movement left over at a waypoint carries on to the next. The Spawner ticks every alive enemy in one loop (`Enemy.Tick`; enemies have no `Update`).
- **Physics.** The enemy root is on layer 11 "Enemy" with a kinematic Rigidbody. In the collision matrix Enemy only meets Default (the `End` trigger) and Ignore Raycast (tower ranges, Pulse and Hindrance), and Ignore Raycast only meets Enemy; `GameLayers` has the constants and `EnemyMask`. Physics steps once per frame (`SimulationMode.Update`) and OnTriggerStay events are off, so don't rely on FixedUpdate or trigger stays.
- **Spawning.** `Spawner` plays a list of `WaveData` assets, each made of parallel lists (`enemiesToSpawn`, `enemySpawnCount`, `spawnDelay`, optional `enemyTraits`).
  - The playable levels use the generated sets in `ScriptableObjects/WaveData/<Beginner01..05|Intermediate01|Intermediate02>/`, written by `Tools/BalanceDashboard/write_waves.py`. Don't hand-edit them; change `wave-design.json` and regenerate. The Spawner lists live in `SimplePrefabs/SpawnerNew.prefab` (Beginner 01), as list overrides on the nested `SpawnerNew` in `Prefabs/Maps/BeginnerLevel0X.prefab` (Beginner 02-05) and in `Prefabs/Maps/IntermediateLevel0x.prefab`. The `SpawnerNew` prefab is untagged; its instances are tagged `Spawner`.
  - Each wave spawns on every lane, pairing `spawnPoints[i]` with `waypoints[i]`. `Spawner.GetLanePath(lane, points)` returns the path an enemy really walks: spawn point, waypoints, cut where the enemy sphere touches the `End` trigger. `Waypoints.Awake` appends only tagged children the serialized list doesn't hold yet, and an enemy that reaches the last waypoint leaks even if it never touched the trigger (`End.ReportExit`; the leak handler ignores enemies that are no longer alive). Spawning runs on game time (first enemy at once, then each entry's delay), several spawns per frame are possible.
  - A wave ends when all lanes finished spawning and `EnemiesAlive` is empty, which fires `OnWaveEnded` and pays the end-of-wave bonus.
  - The game counts as won after the profile's win round (or the last wave); after the last wave that wave repeats with the profile's freeplay scaling applied once per extra round.
- **`WaveGenerator`** is an editor helper: its context menu "Generate Waves Json" writes `Assets/generated.json` (old random generator); "Import Waves From Wave Designer Json" turns a set from `Tools/BalanceDashboard/waves-generated.json` into WaveData assets. It uses Newtonsoft.Json from `com.unity.nuget.newtonsoft-json`, which is listed explicitly in `manifest.json`.
- **Telemetry.** `BalanceTelemetry` attaches itself to game scenes in the Editor and development builds and writes one CSV row per tower type and wave to `Application.persistentDataPath/telemetry` (import in the dashboard's Telemetry tab). Set `BalanceTelemetry.Enabled = false` to turn it off.

The UI follows the "bevelled glass" design in `tasks/ui-redesign/`. It is uGUI + TextMesh Pro, built by `UIRedesignBuilder` into `Prefabs/UI/`. Kit, in-game and main-menu details: see `.claude/rules/ui.md`.

## Unity Workflow
- Usually no Unity Editor is open for this project. Use batch-mode scripts (`-batchmode -nographics -executeMethod ...`) for edits, builds and tests. Do not rely on `unity run`, because it forces -quit.
- If a batch-mode run hangs for more than 10 minutes, kill it and rerun rather than waiting. GUI editor runs can stall on modal dialogs such as TMP Essentials import.
- Verify visual changes with headless screenshots, and inspect them for magenta or flat-blue renders before reporting success.

## Unity 6.5 Gotchas
- Target Unity 6.5. Many sort-mode overloads of FindObjectsByType are deprecated, and so is GetInstanceID. Check the Unity 6.5 API before choosing replacements.
- Qualify `Object` as `UnityEngine.Object` to avoid ambiguity with System.Object.
- After any shader or build-target change, rebuild for the correct target and check that TMP text renders, with no magenta backgrounds.
- Odin Inspector has been removed. Do not reintroduce it.

## Conventions & Pitfalls
- Look up towers and prefabs by prefab key (e.g. 'Default Tower'), never by display name (e.g. 'Laser Tower').
- When rewriting JSON files such as .asmdef, preserve the trailing newline and the original formatting.
- In tests, compare arrays and tuples by value, not by reference. Pick slider test values that do not round to the same step.
- Parallel test or acceptance runs must use separate temp files and never write to a shared variant file.
- Per-frame and per-hit code must not allocate. In this Mono that means:
  - no LINQ and no capturing lambdas;
  - no `foreach` over an interface-typed collection (it boxes the enumerator);
  - no `List.Sort`/`Array.Sort` with a comparer or lambda (it wraps it in a new delegate each call; use a small insertion sort);
  - no `Environment.GetCommandLineArgs` and no `Object.name` per frame;
  - changing HUD text goes through `UIFormat.SetTabular` with a reused `StringBuilder`.
  Check with `-perfProfile` and `ProfileReport`.
